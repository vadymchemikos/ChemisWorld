# Chemis World — стартовий Android-проєкт

Поточна версія: **0.1.0 (інтерфейсний прототип)**

## Що вже є
- Android-застосунок на Kotlin з локальним WebView.
- Адаптивний українськомовний інтерфейс у темному 2D-стилі.
- Початкова панель гри та заготовки розділів.\n- Інтерактивна карта Leaflet з тайлами OpenStreetMap і GeoJSON межами країн.\n- Дозвіл на інтернет і ідентифікація запитів карти як ChemisWorld.
- Локальні HTML/CSS/JS-ресурси без зовнішніх залежностей.

## Важливо
Це перший каркас, а не готова онлайн-гра. Поки що немає облікових записів, сервера, бази даних або синхронізації між гравцями. Карта показує країновий рівень; адміністративні регіони першого та другого рівня ще не підключені. Для карти потрібне інтернет-з’єднання. Кнопки показують повідомлення-заглушки.

## Як відкрити
1. Розпакуйте архів.
2. Відкрийте папку `ChemisWorld` у середовищі, яке підтримує Android Gradle-проєкти (наприклад Android Studio або сумісне Android IDE).
3. Дочекайтеся синхронізації Gradle.
4. Запустіть конфігурацію `app` на Android-пристрої або створіть APK через Build APK.

Потрібні JDK 17 та Android SDK з API 35. Застосунку потрібен дозвіл INTERNET для завантаження карти. Для першої збірки Gradle може завантажити залежності, тому потрібне інтернет-з'єднання.

## Наступні етапи
1. Підключити реальні географічні межі регіонів і інтерактивну карту.
2. Спроєктувати серверну архітектуру, авторизацію та базу даних.
3. Додати ігровий час, регіональні профілі та систему гравців.
4. Реалізувати політику, економіку, дипломатію та події.
5. Тестування мережевої синхронізації й захисту даних.

## Запропонований мережевий напрям
Для повноцінного мультиплеєра потрібен окремий серверний компонент. Його стек і хостинг слід вибрати перед реалізацією авторизації та збереження прогресу. Не зберігайте паролі або секретні ключі у клієнтському APK.

## Карта та атрибуція
- Базова карта використовує тайли OpenStreetMap. Дотримуйтеся політики використання тайлів та показуйте атрибуцію OpenStreetMap.
- Межі країн завантажуються як GeoJSON з відкритого набору даних на основі Natural Earth через публічне дзеркало. Для релізу зафіксуйте конкретну версію набору, перевірте умови ліцензії джерела та бажано зберігайте перевірений GeoJSON у власному сховищі.
- Не використовуйте стандартний сервер тайлів OSM як необмежений production CDN; для великого навантаження потрібен відповідний провайдер або власна інфраструктура.


## Версія 0.3.0 — адміністративна навігація
- Вибір країни на карті.
- Завантаження меж першого адміністративного рівня (ADM1) через GeoBoundaries API.
- Запит меж другого рівня (ADM2) для обраної країни.
- Індикація поточного шляху: Світ → країна → області → райони.

### Обмеження прототипу
- Покриття ADM1/ADM2 відрізняється залежно від країни; для частини країн районний рівень може бути відсутній або мати іншу структуру.
- Поточний прототип запитує ADM2 країни загалом; фільтрація районів за обраною областю залежить від наявних полів у GeoJSON і потребує нормалізації наборів даних.
- Це демонстрація навігації, а не остаточна база адміністративного поділу. Перед запуском мультиплеєра слід імпортувати, перевірити та версіонувати межі у власній базі даних.
- GeoBoundaries API / файли завантажуються з інтернету; у виробничій версії варто кешувати дані та перевірити умови використання і атрибуцію кожного джерела.


## Версія 0.4.0 — регіональне управління та політичний прототип
- Додано картку обраної області або району.
- Додано локальне створення партій із назвою, напрямом і короткою програмою.
- Партії зберігаються в localStorage на пристрої користувача.
- Додано демонстраційні вибори для регіонів із двома або більше партіями.

### Важливі обмеження
- Це локальний прототип: партії не видно іншим гравцям і вони не синхронізуються між пристроями.
- Тестові вибори використовують умовні випадкові результати та не є повноцінною моделлю виборів.
- Статистика населення, площі та економіки ще не підключена до перевірених даних.
- Повноцінний мультиплеєр потребуватиме серверної авторизації, бази даних, API, валідації дій на сервері та захисту від підробки результатів клієнтом.


## Версія 0.5.0 — незалежна економіка регіонів
- Кожен регіон має окремий бюджет, ставку податку, рівень інфраструктури та номер економічного ходу.
- Додано умовні доходи за хід.
- Додано інвестицію в інфраструктуру за ігрову валюту CW₵.
- Економічні дані зберігаються окремо за назвою регіону в localStorage.
- Зміни в одному регіоні не змінюють бюджет іншого.

### Обмеження
Це локальна економічна симуляція з умовними ігровими значеннями. Вона не використовує реальні бюджети, ВВП чи податкові ставки та ще не синхронізується між гравцями. Для мультиплеєра економічні операції мають виконуватися й перевірятися сервером, щоб клієнт не міг самостійно створювати валюту або підробляти транзакції.


## Версія 0.6.0 — заснування держав і територіальна належність
- Додано форму заснування держави: назва, столиця, основний колір прапора та символ.
- Перша обрана територія стає початковою територією держави.
- Додано приєднання інших вільних територій до створеної держави.
- Одна територія може належати лише одній державі в локальному прототипі.
- Додано список створених держав із кількістю територій та столицею.
- Збереження здійснюється локально в localStorage.

### Обмеження версії 0.6.0
- Держави та їхні кордони поки що видимі лише на пристрої, де їх створили.
- Це не змінює геополітичну карту для інших гравців.
- Немає серверної перевірки прав на території, дипломатії, визнання держав або онлайн-синхронізації.
- Колір і символ — попередня візуальна модель прапора, не редактор повноцінного зображення.
- Для онлайн-версії потрібні серверна база даних, транзакційна перевірка власності територій та історія змін кордонів.


## Версія 0.7.0 — державне управління
- Додано окрему панель управління кожною створеною державою.
- Можна призначити главу держави.

## Версія 1.0.0 — серверна основа онлайн-акаунтів
- Додано окремий Node.js API у каталозі `backend/`.
- Реєстрація та вхід за нікнеймом і паролем.
- Паролі зберігаються лише у вигляді scrypt-хешів із випадковою сіллю.
- Підписані токени сесій, обмеження частоти спроб.
- Профіль гравця та авторизований каталог гравців.
- Android/WebView-клієнт отримав поля для HTTPS-адреси API, реєстрації, входу, виходу та пошуку гравців.
- Версію Android-застосунку оновлено до 1.0.0.

### Що потрібно зробити перед реальним онлайн-запуском
1. Розгорнути `backend/` на Node.js-хостингу з HTTPS.
2. Створити власний секрет `JWT_SECRET` і налаштувати дозволені домени `ALLOWED_ORIGINS`.
3. Перевірити сервер на окремому тестовому середовищі та налаштувати резервні копії БД.
4. Вказати HTTPS-адресу сервера в онлайн-панелі застосунку.

### Обмеження v1.0.0
- Серверний код підготовлено, але він не розгорнутий і не працює в інтернеті автоматично.
- Для запуску API потрібні Node.js 20+, `npm install` і налаштування `.env`.
- Онлайн-акаунти та каталог гравців — перші мережеві функції. Держави, партії, економіка, вибори та дипломатія ще не синхронізуються між гравцями.
- Це основа для подальшого розвитку, а не готовий production-мультиплеєр чи скомпільований APK.

- Це не готовий публічний мультиплеєрний реліз; потрібні тестування, модерація, резервні копії та посилення захисту API.

## Версія 1.3.0 — парламент і уряд
- Після завершення виборів сервер розподіляє 100 парламентських місць пропорційно голосам партій (метод найбільших залишків).
- Для кожного законопроєкту гравці можуть подати один голос «за» або «проти»; повторний голос з того самого акаунта блокується.
- Власник держави підтверджує підсумок: закон ухвалюється або відхиляється за більшістю голосів.
- Після виборів власник може сформувати уряд, зазначити прем’єр-міністра та міністрів за портфелями.
- Парламентські місця та склад уряду повертаються сервером у політичному огляді держави.

Обмеження: це перша ітерація ігрової парламентської моделі. Голосування за закон доступне всім авторизованим гравцям, а не лише перевіреним депутатам; розподіл місць не призначає персональних депутатів. Власник держави формує уряд і підтверджує результат законопроєкту. Справжній запуск вимагає серверного розгортання, HTTPS, тестів, модерації та додаткового аудиту безпеки.


## Версія 1.4.0 — територіальне управління
- Власник держави може призначати керівника для території, що входить до складу його держави; гравець має бути зареєстрований у системі.
- Для території можна оголосити місцеві вибори з 2–20 кандидатами.
- Кожен акаунт може віддати один голос у конкретних місцевих виборах.
- Після завершення голосування формується місцева рада на 15 місць із пропорційним розподілом місць між кандидатами.
- Доступні перегляд керівників, результатів місцевих виборів і складу рад.

Обмеження: ключ території потрібно вводити точно так, як він записаний у складі держави. У цій версії керівника призначає власник держави; окремі повноваження губернатора, бюджетні повноваження місцевої ради та вибори мера ще не реалізовані. Виборці поки не обмежені членством або проживанням у конкретній території. Функції доступні після розгортання backend-сервера.

- Незалежний бюджет кожної території держави з окремою казною, податковою ставкою та рівнем інфраструктури.
- Керівник регіону або власник держави може встановити місцевий податок від 0 до 25% та отримати дохід за економічний цикл.
- Будівництво шкіл, лікарень, доріг, культурних центрів і систем водопостачання за кошти конкретного регіону.
- Місцеві законопроєкти, голосування «за/проти» та підтвердження результату керівником регіону або власником держави.
- Окремі вибори мера з одним голосом на акаунт; після завершення переможець зберігається як мер території.

Обмеження: економічні значення та доходи є ігровими умовними величинами, а не реальною статистикою. Дохід нараховується за ручною дією «Отримати дохід регіону», без фонового таймера. Виборці поки не перевіряються за місцем проживання. Власник держави оголошує вибори мера та завершує їх; окремий механізм реєстрації кандидатів і незалежної виборчої комісії ще не реалізований. Сервер необхідно розгорнути для спільної роботи гравців.


## Версія 1.6.0 — інтерактивне управління картою
- Кнопки навігації: повернення до всього світу та наближення до вибраної країни.
- Окреме завантаження областей/провінцій та районів із відкритих GeoBoundaries.
- Вибір адміністративної території на карті з формуванням унікального ключа `ISO:код`.
- Додавання вибраної території до власної онлайн-держави через серверний реєстр територій.
- Територія не може бути додана двічі, а змінювати склад держави може лише її власник.

Обмеження: геодані завантажуються з відкритих зовнішніх сервісів і залежать від доступності мережі та покриття набору даних. Райони можуть бути відсутні для окремих країн; відповідність району конкретній області ще потребує точнішої перевірки атрибутів набору. Карта не змінює міжнародні кордони OSM/Natural Earth автоматично: ігрові володіння зберігаються окремо на сервері. Для справжньої спільної карти сервер має бути розгорнутий.


## Версія 1.7.0 — міста та міський розвиток
- Реєстр міст у межах конкретної території держави.
- Заснування міста керівником регіону або власником держави; назва та початкове населення перевіряються сервером.
- Призначення міського голови з-поміж зареєстрованих гравців.
- Міські проєкти: житлові квартали, школи, медичні центри, транспортні вузли, парки та комунальні мережі.

Обмеження: міста поки є записами всередині регіону, без окремих географічних координат/точок на мапі. Міського голову призначає керівник регіону або власник держави; виборів мера міста ще немає. Населення та вартість проєктів — умовні ігрові величини. Приріст населення запускається вручну, а не автоматично. Сервер має бути розгорнутий для спільного доступу гравців.


## Версія 1.8.0 — міське самоврядування
- Міські вибори мера та міської ради серед зареєстрованих гравців.

Для спільної гри backend має бути розгорнутий і налаштований через HTTPS.

### Як отримати APK через GitHub Actions
1. Завантажте цей проєкт у власний GitHub-репозиторій.
2. Відкрийте вкладку Actions.
3. Виберіть workflow **Android APK build** та натисніть **Run workflow** (або зробіть push у `main`).
4. Дочекайтеся успішного завершення job.
5. У нижній частині сторінки запуску завантажте artifact `chemis-world-debug-apk`.

### Вимоги для локальної збірки
- JDK 17.
- Gradle 8.9.
- Android SDK Platform 35 та Build Tools, доступні через Android SDK Manager.
- Запуск із кореня проєкту: `gradle :app:assembleDebug`.

Примітка: цей робочий сеанс не має встановленого Gradle/Android SDK, тому локальну компіляцію APK тут не виконано. Workflow підготовлений, але його реальний результат можна підтвердити лише після запуску в GitHub Actions. Debug APK не є підписаним production-релізом.
